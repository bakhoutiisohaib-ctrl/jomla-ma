## 2. ما نُفذ

### مساحة المشتري

ترويسة وتنقل وبطاقات بهوية Atlas: أخضر داكن، خلفيات هادئة، تباعد أوضح، أزرار بارزة، وRTL/LTR. تعرض النظرة العامة أعداد الطلبات التي تحتاج مراجعة، والمنتظرة، والاتفاقات المقبولة. التصفية تستخدم الحالات الموجودة فقط: `pending / responded / deciding / accepted / rejected`، مع تجميع للمراجعة والاستكمال.

توضح البطاقات السعر والوحدة والكمية والإجمالي والعملة المتاحة. تُعطى أولوية لبيانات الاتفاق المثبتة ثم نسخة العرض؛ لا يُعاد تفسير الاتفاق من منتج عُدّل لاحقاً. تظهر رسالة واضحة بأن القبول اتفاق تجاري، ولا يمثل دفعاً أو شحناً أو تسليماً مكتملاً. بقيت طلبات التوريد وإجراءاتها على المسارات الحالية.

### المحادثات والعروض

حوار مشترك للمشتري والمورد، بملخص تجاري وسجل عروض بجانب المحادثة على الحاسوب. على هاتف المشتري يمكن الانتقال بين «العرض والاتفاق» و«المراسلات». تعرض الرسائل الاسم والدور والتوقيت المسجل فعلياً. يتميز العرض الحالي بإطاره وعنوانه، وتظهر العروض السابقة أو المستبدلة دون أزرار قرار.

القبول والرفض لهما مراجعة وتأكيد داخل الحوار، يشملان السعر والكمية والإجمالي. يمنع قفل متزامن إرسال قرارين من نقرتين سريعتين، وتعطَّل الإجراءات أثناء الطلب. يعرض تاريخ صلاحية العرض عند وجوده، ويُعطل القرار على عرض منتهي، مع بقاء تحقق الخادم هو المرجع.

حُفظت `deciding` ونتيجة 202: تطبق الواجهة نتيجة القرار التي أعادها الخادم قبل إعادة القراءة. لا تستطيع قراءة أقدم إرجاع قرار محفوظ أو اتفاق مكتمل إلى حالة سابقة. عند انقطاع غير محسوم، تمنع الواجهة قراراً آخر وتطلب تحديث الحالة. زر الاستكمال يرسل **action وofferId المحفوظين نفسيهما**. لا توجد إعادة تلقائية لقرار جديد أو استنتاج محلي لنجاحه. بعد القرار النهائي تختفي أدوات التفاوض وفق الحالة الحالية.

بقي `CommercialAgreement` وخدمات Phase B كما هما، بما في ذلك تحذير السجلات القديمة التي لا تحتوي نسخة تاريخية. تغيّر عرض حوار المورد فقط؛ لم تتغير معالجات رسائله وعروضه، ولا لوحة المنتجات والمتاجر أو المحرر.

### الإشعارات والجلسة

مركز المشتري يعرض العنوان والنوع والتاريخ وحالة القراءة حسب البيانات الموجودة، مع فلتر الكل/غير المقروء وإجراءات القراءة الحالية. فتح RFQ يمر بطلب قراءة مصادق للتحقق من صلاحية الحساب قبل عرض الحوار؛ رفض الصلاحية لا يفتح الطلب ولا يعلّم الإشعار كمقروء. طلب التوريد يتحقق من قائمة المشتري المصرح بها.

الجرس ومركز المشتري يستخدمان حالة واحدة ومصدر تحديث واحد؛ لم يُضف جرس مستقل بجدول تحديث آخر. التحديث كل 30 ثانية عند ظهور الصفحة، وعند العودة والتركيز، وبعد الإجراءات. بقي جرس الصفحات العامة ومركز المورد ووظائف إنشاء الإشعارات دون تغيير. لم تُضف أنواع أو خدمات Push أو Email أو WhatsApp.

تُعاد تهيئة مساحة المشتري حسب الجلسة والحساب، وتُلغى الطلبات السابقة. تتحقق كل استجابة من الجلسة الحالية ورقم طلب القراءة أو المحادثة، فلا تستبدل استجابة متأخرة بيانات الحساب الجديد. فشل قراءة العداد يعرض حالة غير مؤكدة عوض ادعاء صفر إشعارات.

### لوحة المفاتيح والحالات

رابط تجاوز للمحتوى، وتركيز مرئي، وتسميات حقول، وحالات تحميل وخطأ وفراغ. الحوار يحصر Tab داخله، ويدعم Escape، ويعيد التركيز إلى زر الفتح عند الإغلاق. يتعطل إغلاقه أثناء الإجراء الجاري. التأكيد داخل الصفحة لا يستخدم `window.confirm`. تبقى الرسالة عند فشل الإرسال.

## 6. API والبيانات والبيئة

لا تغيير في عقود API أو أسماء الحقول أو مخططات MongoDB. تستهلك الواجهة `rfq / processing / decision / revision / thread / offers / unreadCount` الموجودة فعلياً؛ لم يُضف endpoint أو مسار URL جديد. لم تتغير خدمات القرار أو الاسترجاع أو سياسات الصور، ولم تنشأ محفظة أو عملية دفع أو شحن أو Order جديد؛ عدد Orders في قاعدة الرحلة صفر.

شُغلت ثلاث قواعد MongoMemoryServer مستقلة standalone على loopback مع بيانات وصور اصطناعية، وإعدادات وأسرار اختبار عشوائية في ذاكرة العملية؛ عُطل اتصال قاعدة المشروع وتحميل dotenv والخدمات الخارجية في أدوات المعاينة. لم يُستخدم اتصال القاعدة الأصلية. أُغلقت الخوادم والقواعد وأُزيلت مجلداتها المؤقتة الثلاثة؛ تؤكد ملفات `preview-shutdown.json` ذلك. أُغلقت تبويبات الفحص وأُلغي ضبط قياس المتصفح.

## 7. الحدود المتبقية ونقطة التوقف

- الإشعارات تستخدم التحديث الدوري الحالي، وليست فورية. الخدمة تعيد أحدث100 إشعار، بينما العداد قد يشمل إشعارات أقدم؛ توضح الواجهة هذا الحد. لا pagination أو قنوات إرسال جديدة.
- إثبات المرة الواحدة هنا يخص آثار قرار B وحالاته المختبرة. لم يُضف بروتوكول جديد لعدم تكرار الرسائل أو لإنشاء RFQ أو عروض التوريد؛ بقي سلوكها الخادمي الحالي.
- التعافي يعتمد على عامل Phase B الموجود أو إعادة الاستكمال المصرح بها. الواجهة لا تحول 202 إلى نجاح نهائي من تلقاء نفسها؛ عند تعطل الاستكمال تبقى الحالة ظاهرة ومقفلة.
- الاتفاقات القديمة بلا snapshot تحتفظ بالتحذير الحالي ولا تُستكمل بياناتها تخميناً. طلب مزروع أو قديم بلا محادثة لا تُنشأ له محادثة بتدخل تخميني في هذه المرحلة.
- فحص الهاتف بمحاكاة قياس المتصفح المحلي، وليس اختبار جهاز فعلي أو جميع المتصفحات. اختُبرت لوحة المفاتيح والتركيز؛ لم يُنفذ تدقيق قارئ شاشة شامل أو قياس أداء شبكي إنتاجي.
- لم تُعدّل وظائف D2-A ولا نظام توثيق المورد أو الدفع والشحن. أي تغييرات خادمية أو تحسينات خارج النطاق تحتاج مرحلة وموافقة مستقلة.

**توقف العمل عند D2-B. لا تبدأ مرحلة جديدة قبل اختيار وموافقة المالك.**
