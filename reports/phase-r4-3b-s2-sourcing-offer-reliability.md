# Jomla.ma — R4-3B / S2: Reliable Sourcing Offers

التاريخ: 2026-10-25. **S2 فقط**، محلياً؛ لا تفعيل للبيئة الأصلية. **الحكم: PASS محلياً. الأصلية NOT ACTIVATED / NOT VERIFIED؛ S3 غير منفذة.**

## 1. المشكلة والمرجع

كان إرسال عرض Sourcing يحفظ العرض واستبدال السابق ثم ينشئ الإشعار في كتابة منفصلة. فشل الإشعار أو فقد تأكيد الكتابة/HTTP كان يسمح بإعادة إنشاء عرض آخر أو بقاء أثر مطلوب ناقصاً. optimisticConcurrency القديم يمنع بعض الكتابات المتعارضة، لكنه لا يوفر إيصال إعادة أو استكمال آثار بعد إعادة تشغيل Node.

المراجع محفوظة دون تعديل: [تقرير S1](C:/Users/hp/jomla-ma/reports/phase-r4-3b-s1-idempotent-sourcing-creation.md)، و[تدقيق R4-3B وخطته](C:/JomlaVerification/R4-3B-analysis-20261025T130307Z/phase-r4-3b-sourcing-reliability-audit-plan.md). تشخيصات التدقيق الخارجية السابقة كانت تثبت العيب؛ ليست اختبارات إصلاح، ولم تُعدّل أو تدخل ضمن أعداد النجاح الجديدة.

## 2. البروتوكول المنفذ

الحقول الجديدة اختيارية داخل SourcingRequest فقط: operation من نوع sourcing_offer، وإيصال submission وcommercialSnapshot داخل العرض الجديد. لا backfill أو تخمين لبيانات اتفاقات/عروض تاريخية.

1. مفتاح Idempotency-Key إلزامي لإرسال العرض. البصمة تربط الطلب ومالك المورد والمدخلات المقبولة بعد تطبيعها؛ الفاعل واسمه ودوره وملكيته من الجلسة، لا من الجسم. زميل مخول من المالك نفسه يمكنه استكمال المحاولة مع بقاء هوية الفاعل الأول.
2. يُفحص الإيصال الدائم قبل رفض الإعادة بسبب الحالة التجارية: نفس المالك والمفتاح والمحتوى يعيد العرض الأصلي بحالته الحالية، حتى بعد استبداله أو قبوله. المحتوى المختلف409. مفتاح جديد يمثل محاولة مستقلة، ولا يُستعمل تشابه السعر/النص/الزمن لمنعها.
3. حجز واحد بكتابة ذرية وCAS على __v وغياب عملية أخرى وإيصال مطابق. يحفظ المدخلات والمعرّفات المستقرة ونسخة التسعير وبصمة الحالة التجارية. **الحجز لا يضيف عرضاً active ولا يستبدل السابق**.
4. يتحقق المستكمل من نوع النية وهوياتها والحالة التجارية وصلاحية الفاعل الأصلي الحالية وعضويته ومالك المورد. يثبت إشعار sourcing_offer الحالي بمعرف محفوظ وبـ$setOnInsert، ثم يتحقق من المستلم والنوع والطلب والتوقيت وعدم نسبته لقرار آخر. نص الإشعار مشتق من النوع ومعرف المورد افتراضياً؛ لا نص موثوق من العميل أو نوع إشعار جديد. readAt لا يُعاد ضبطه.
5. بعد إعادة التحقق: كتابة تجارية واحدة محمية تضيف العرض والإيصال والنسخة المثبتة، وتستبدل active التابعة للمورد نفسه فقط، وتحسب العداد، وترفع __v وتزيل operation. استُخدمت كتابة native لهذه الخطوة كي لا يُسقط تحويل مصفوفة تاريخية كاملة عبر Mongoose حقولاً قديمة غير معروفة. لا حذف للتاريخ.
6. خطأ الكتابة أو فقد تأكيدها لا يعد إثبات فشل أو نجاح وحده: تُقرأ النية/الإيصال/الإشعار من primary وتُتحقق الهوية والمحتوى. الإعادة المكتملة لا تنشئ آثاراً ولا تستكمل عملية أخرى أحدث.

الإدراج والنشر يطلبان w:1,j:true. لا معاملات متعددة المستندات، ولا قفل ذاكرة يعتمد عليه منع التكرار. metadata المحاولات لا ترفع النسخة التجارية؛ الحجز والنشر يرفعان __v كل منهما مرة، ولذلك تغير النسخة وحده لا يعني نشر العرض.

## 3. التعليق والخصوصية والواجهة

- 200 يعني تأكيد العرض؛ 202 يعني نية محفوظة قيد الاستكمال، وليس نجاحاً نهائياً. 503 يعني تعذر تأكيد النتيجة. تعارض المحتوى SOURCING_OFFER_KEY_CONFLICT يختلف عن التعارض المؤقت SOURCING_OPERATION_PENDING.
- بقي POST /api/sourcing/:id/quote مع رأس إلزامي وفق `[A-Za-z0-9_-]{16,128}`؛ غيابه/بطلانه400 بلا حجز. أضيف POST /api/sourcing/:id/operations/:operationId/retry لاستكمال المدخلات المحفوظة، بمصادقة المورد/الموظف وصلاحية المالك؛ لا بيانات عرض جديدة أو مفتاح جديد في هذا المسار.
- جميع قراءات واستجابات Sourcing انتقلت إلى DTOs صريحة قبل إضافة البيانات التشغيلية. لا مفاتيح أو بصمات أو إيصالات submission أو سجل خام في المخرجات. المورد لا يرى عروض منافسيه أو اتصال/هوية المشتري. buyerId المخزن داخل النسخة التجارية لا يُنشر للمورد.
- ملخص pending آمن للمشاهد المخول. تفاصيل الاستكمال offerRecovery متاحة لمالك المورد وموظفيه المخولين فقط إذا اتفقت هويات الطلب والمشتري ومالك الفاعل والنسخة التجارية. عند تعارضها تُحجب التفاصيل. requiresReview علامة آمنة دون سجل الخطأ الخام.
- قد يظهر الإشعار قبل النشر، لكنه يفتح الطلب المملوك للمشتري عبر المسار الحالي، ويعرض «لم يُنشر العرض الجديد بعد». العرض الجديد ليس ضمن quotes؛ أزرار قبول/رفض السابق معطلة، والخادم يمنعها أيضاً. أضيف حارس pending وحارس سباق النسخة فقط إلى القرار؛ لم يُنفذ S3.
- هوية Atlas محفوظة، مع رسائل عربية/فرنسية. الواجهة تثبت المفتاح والمدخلات عند غياب التأكيد، وتمنع الضغط المزدوج والردود المتأخرة بعد تبديل الحساب/unmount. النافذة والبيانات مرتبطة بالجلسة التي قرأتها. لا POST عند الفتح أو الدخول.
- عند إعادة فتح الصفحة، يعيد الخادم بيانات العملية المحفوظة لصاحبها، وتظهر مجمدة مع زر استكمال. بعد معرفة operationId يمكن إغلاق النافذة؛ قبل حسم محاولة محلية بلا معرف محفوظ، يمنع الإغلاق العرضي لحفظ المفتاح.
- لا يحفظ المكوّن نسخة JWT أو مدخلات المحاولة في تخزين إضافي على القرص؛ يستعمل جلسة المصادقة القائمة. الذاكرة المحلية تضيع عند تحديث الصفحة/إغلاق التبويب. العملية المحفوظة قابلة للاسترجاع من الخادم؛ إذا فُقد المفتاح قبل معرفة حفظها، تُراجع العروض ولا يُخمن تطابق محاولة بالنص أو السعر أو الوقت.

## 4. الحجم وعامل الاستكمال

قبل الحجز تُحسب BSON للحالة المعلقة ولحالة تتضمن الحجز والعرض النهائي معاً، من المستند الكامل بما فيه إيصال S1 والحقول القديمة غير المعروفة. الحد المحافظ **16 MiB ناقص 256 KiB**. الهامش يغطي metadata المحدودة ونمو الأرقام وتأطير الأمر. يعاد الفحص قبل النشر. تجاوز الحجم قبل الحجز413 بلا نية/إشعار أو حذف عروض. الكتابات التجارية الأخرى ممنوعة أثناء pending، فلا ينمو المستند عبرها بين الحجز والنشر.

عامل مستقل خاص بـSourcing يعمل من API وworker: دفعة25 افتراضياً، سقف100، استطلاع5 ثوان، backoff تصاعدي بسقف60 ثانية، وحدود10 ثوان للاستعلام/الكتابة. الإيقاف يلغي الاستطلاع وينتظر الجاري حتى15 ثانية، ويترك النية الدائمة إذا لم يُصرف الجاري. اختُبر تشغيل أكثر من عملية دون قفل ذاكرة.

التعارض لا يفرض تغيير ملكية أو سعر أو نتيجة نهائية. تُحفظ حالة pending مع رمز آمن وbackoff عندما تكون هوية النية قابلة للتحقق؛ الهوية التالفة التي لا يصح تحديثها تبقى كما هي مع بلاغ تشغيلي آمن. لا TTL يمسح النية. سحب صلاحية الفاعل الأصلي قد يوقف استكمال عمليته إلى حين معالجة معتمدة؛ لا استبدال تلقائي للفاعل بزميل آخر.

لم تُقرأ القاعدة الأصلية، ولذلك **عدد العمليات المعلقة فيها غير معلوم**. المراقبة المستقبلية تحتاج فحص operation الموجود عموماً، بما فيه الأنواع/الإصدارات التالفة، وليس مرشح العامل السليم فقط. كثرة السجلات المتناقضة قد تستلزم تدخلاً لمنع إعاقة تقدم الدفعات المحدودة. أمثلة القراءة التشغيلية، دون تنفيذها، في [وثيقة التشغيل](C:/Users/hp/jomla-ma/docs/sourcing-s2-activation-and-recovery.md).
