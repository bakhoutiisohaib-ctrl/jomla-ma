# دليل التشغيل والانتقال

## إعداد البيئة

- Node.js حديث مدعوم، وMongoDB متاح، وتثبيت الاعتماديات بواسطة npm ci من أقفال الحزم.
- JWT_SECRET فريد وطويل، لا قيمة تجريبية. الإنتاج يرفض المفاتيح القصيرة أو الواضحة كأمثلة.
- CORS_ORIGIN قائمة أصول محددة مفصولة بفواصل. لا تستخدم wildcard مع بيانات الاعتماد.
- اضبط TRUST_PROXY=1 فقط إذا كان التطبيق فعلاً خلف proxy واحد موثوق يزيل رؤوس العميل المزورة؛ يبقى معطلاً افتراضياً.
- الواجهة تستعمل /api افتراضياً؛ اضبط REACT_APP_API_URL قبل build إذا كان API على أصل مختلف. الصور المحلية تتبع أصل API.
- GET /health/live للحياة، وGET /health/ready للاستعداد؛ الأخير يعيد503 دون قاعدة بيانات متصلة.
- Redis cache اختياري؛ غيابه يستخدم بديل الذاكرة. ليس queue للمهام.

## الحسابات والمنظمات

أنشئ أول مشرف من الطرفية داخل backend:

    node scripts/create-admin.js --name "Administrator" --email "admin@example.com"

أدخل كلمة المرور في المطالبة المخفية. لا تضعها في معاملات الأمر أو سجل الطرفية. المسار HTTP القديم للإعداد ملغى.

التوكنات القديمة دون tokenVersion تبطل عمداً؛ يكفي الدخول مجدداً لإصدار جلسة جديدة. تسجيل الخروج يبطل جميع جلسات الحساب. سحب الدور أو تعطيل الحساب أو عضوية الموظف يُراجع في قاعدة البيانات عند كل طلب.

المورد ينشئ/يكمل شركة فعلية، ومتجراً تنتظر مراجعته الإدارة. الموظف يقبل دعوة محفوظة برمز سري يشاركه المالك خارج المنصة عبر وسيلة موثوقة. لم يضف إرسال بريد آلي. الصلاحيات منفصلة لإدارة المنتجات والمتجر وRFQ.

## الانتقال من البيانات السابقة

لم تُعدّل قاعدة بيانات حقيقية في هذه المهمة. قبل نشر النسخة الجديدة:

1. خذ نسخة احتياطية من قاعدة Mongo ومجلد uploads، واحتفظ بالإعدادات والأسرار في مخزن منفصل محمي.
2. جرب الاستعادة في قاعدة منفصلة، وقارن عدد المستندات ومراجع الصور وافتح عينات منها.
3. اطلب من الموردين تسجيل الدخول وإكمال الشركة والمتجر والصورة والوصف وحقوق الصورة والتوفر والعملة والوحدة وMOQ ثم اعتماد النشر.
4. راجع واعتمد المتاجر إدارياً. المنتج القديم الذي لا يحمل storeId أو دليل اعتماد/حقوق/تأكيد توفر لا يظهر للعامة. لا تعين هذه الحقول آلياً لتجاوز المراجعة.
5. طلبات RFQ القديمة بلا buyerId لا تنسب إلى حساب بمجرد تطابق الهاتف؛ يلزم تحقق ومراجعة يدوية قبل أي ترحيل للملكية.
6. seeds القديمة موقوفة لحماية البيانات. المعاينة المعزولة مخصصة للاختبار فقط.

## الصور والوثائق

التخزين الافتراضي ملفات تحت backend/uploads. يمكن تعيين UPLOADS_DIR إلى مسار مطلق لقرص دائم؛ يجب أن يرى API والعامل المجلد نفسه. القرص المؤقت لا يصلح لحفظ الصور. انسخه مع نسخ قاعدة البيانات. إعداد Cloudinary القديم ليس مساراً فعالاً في هذا التطبيق.

توجد حدود10MB وفحص MIME والتوقيع والبنية، وفك كامل للبكسلات بواسطة sharp بحد25 مليون بكسل و12000 لكل بُعد. يرفض الرفع الصور المتحركة. PNG يفحص CRC والبيانات المضغوطة أيضاً. لا يوجد مضاد فيروسات. لا يوجد تحسين توليدي يغيّر حقيقة المنتج.

وثائق التوثيق لا ترجع ضمن الملف العام؛ استعمل روابط HTTPS خاصة/موقعة يمكن للمشرف الوصول إليها. uploads العام مخصص لصور الكتالوج، وليس مخزناً لوثائق الشركة الحساسة. يلزم إعداد تخزين خاص مناسب عند تشغيل توثيق حقيقي.

## الذكاء الاصطناعي والبحث الخارجي

CLAUDE_API_KEY وCLAUDE_MODEL اختياريان. إن غاب الإعداد، يعاد503 صريح وتبقى الصورة المرفوعة متاحة للإدخال اليدوي. إن وُجد الإعداد، يعيد enhance استجابة202 ومهمة محفوظة في MongoDB؛ تتابعها الواجهة عبر /api/jobs/:id. فشل المزود يظهر كفشل مهمة بعد محاولات محدودة، وتظل الصورة والحقول اليدوية متاحة. لا يولّد النظام أسعاراً أو MOQ أو مخزوناً من الصورة. المورد يراجع الوصف المرئي ويحدد المعلومات التجارية بنفسه. راجع [دليل المهام](JOBS.md).

البحث بالصورة يعمل محلياً من بكسلات الصور دون مفتاح AI، عبر متجهات اللون والتوزيع المكاني والحواف. تحفظ وتُفهرس الصور المحلية عند حفظ المنتج بواسطة مهمة خلفية. المنتجات السابقة تحتاج تشغيل npm run visual:index -- --apply --public-only بعد نسخ احتياطي ومراجعة البيانات. التطابق يعني ملف الصورة نفسه فقط؛ التشابه ليس تحققاً من هوية المنتج ولا احتمال دقة. صور HTTPS البعيدة لا تُجلب آلياً ولا تُفهرس. راجع [دليل البحث البصري](VISUAL_SEARCH.md).

الاكتشاف الخارجي عبر Brave معطل افتراضياً. لتفعيله بعد مراجعة المشغل لاتفاق الخدمة وطبيعة الاستخدام:

- EXTERNAL_DISCOVERY_ENABLED=true
- EXTERNAL_DISCOVERY_PROVIDER=brave
- BRAVE_SEARCH_API_KEY=مفتاح المشغل
- EXTERNAL_DISCOVERY_TERMS_ACCEPTED=true
- EXTERNAL_DISCOVERY_TERMS_REFERENCE=رابطHTTPSللشروطالتيتمتمراجعتها

وثائق المزود: https://api-dashboard.search.brave.com/api-reference/web/search/get . إعداد المتغير لا يعني أن النظام تحقق قانونياً من كل مصدر أو مورد. النتائج خارجية وغير موثقة، لا تمثل مخزوناً مؤكداً، وتعرض منفصلة عند غياب النتائج الداخلية. يحفظ المصدر والاستعلام والتاريخ ومرجع الشروط. حدها5 ومهلة5ثوان. الاختبارات تحاكي المزود؛ لم تجر طلبات حية بمفاتيح المستخدم.

## النسخ الاحتياطي والمراقبة

توجد أدوات نسخ BSON والفهارس والصور وفحص SHA-256 والاستعادة إلى قاعدة جديدة فقط. راجع [دليل النسخ والاستعادة](BACKUPS.md)، وابدأ من جذر المشروع بـ node scripts/backup.js --help. أوقف الكتابة مؤقتاً لاتساق النسخة متعددة المجموعات؛ أداة النسخ لا توفر snapshot كلياً. لا تنسخ ملفات الأسرار إلى المستودع. حدد دورية النسخ والاحتفاظ ومسؤول الاستعادة خارج الكود؛ لا توجد مهمة نسخ مجدولة أنشأها هذا التغيير. يمكن استخدام أدوات MongoDB الأصلية للأنواع الخاصة أو قواعد البيانات الكبيرة.

راقب readiness وأخطاء5xx وفشل AI والرفع وتراكم AuditLog.phase=pending أوfailed. يكتب auditedChange نية متينة قبل التعديل ثم completed قبل إعلان النجاح، وهو متوافق مع Mongo standalone. ليس معاملة atomic: قد تبقى pending عند تعطل العملية بين الكتابتين، ويجب مراجعتها. عند الحاجة إلى ضمان معاملات متعدد المستندات، خطط لـreplica set ومعاملات/outbox واختبارات تعافٍ.

طابور المهام محفوظ في MongoDB ويعمل على standalone. الوضع الافتراضي JOB_WORKER_MODE=embedded يبدأ العامل مع API؛ لتشغيله مستقلاً اضبط external وشغّل npm run worker. تدعم المهام الحجز الذري، heartbeat، استعادة الحجوزات المنتهية، المحاولات المحدودة والمهل ومنع تكرار المفتاح والبيانات. التنفيذ at-least-once؛ لا تدّع exactly-once لأثر خارجي. راقب تراكم pending/retry_wait والحالات failed عبر GET /api/jobs/mine والمشرف. نتائج التحليل قابلة للاسترجاع من «مهام الصور» ولا تنشر تلقائياً.

الإشعارات داخل التطبيق محفوظة وتحدث دورياً. لا بريد/SMS/push خارجي أو ضمان تجاري أو شحن/دفع مدمج.

## حدود الاعتماد

النجاح المحلي لا يعادل اعتماد إنتاج أو تجربة سوق. تبقى مقابلات الموردين والمشترين، اختيار فئات ومدينة التجربة، مراجعة المصادر وشروطها، اختبار النسخة الفعلية في بيئة منفصلة، قياس دقة مطابق/مشابه على مجموعة موسومة حقيقية، وتجربة الهاتف مع مستخدمين حقيقيين. benchmark الصور التركيبية اختبار تقني وليس دقة سوق. بقي React/Express/Mongo كما هو؛ لم تنفذ هجرة Next/TypeScript/PostgreSQL لأن التصور غير نهائي.
