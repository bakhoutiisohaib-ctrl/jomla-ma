# النسخ الاحتياطي والاستعادة

الأداتان تنسخان MongoDB والصور المحلية فعلياً، دون اشتراط تثبيت `mongodump` أو `mongorestore`. تستخدمان MongoDB driver الموجود ضمن Mongoose. النسخة ملفّات محلية في مجلد جديد، وليست نسخة سحابية أو جدولاً مجدولاً.

## إنشاء نسخة

1. أوقف الكتابة من التطبيق والمهام الخلفية طوال نسخ قاعدة البيانات والصور. يمكن إبقاء القراءة فقط. النسخة منطقية لكل مجموعة وليست snapshot معاملات متعددة المجموعات؛ لا تضمن اتساقاً لحظياً إذا استمرت الكتابة. تستخدم قراءة `local` لتعمل أيضاً مع MongoDB standalone.
2. اضبط `MONGODB_URI` بحساب يملك القراءة وقراءة تعريف المجموعات والفهارس، وحدد اسم قاعدة صريحاً في URI. الأداة تقرأ `backend/.env` مع احترام متغيرات البيئة الموجودة. لا تضع URI أو كلمة مرور في معاملات الأمر.
3. جهّز مجلداً أباً محمياً خارج مستودع Git، ثم شغّل من جذر المشروع، مع اسم وجهة غير موجود:

```powershell
node scripts/backup.js --out "D:\JomlaBackups\pilot-2026-10-19-01"
```

تُنسخ الصور من `UPLOADS_DIR` إن كان مضبوطاً، وإلا من `backend/uploads`. لتحديد موقع التخزين الذي يستخدمه التطبيق فعلياً:

```powershell
node scripts/backup.js --out "D:\JomlaBackups\pilot-2026-10-19-02" --uploads "D:\JomlaMedia\uploads"
```

غياب مجلد الصور خطأ صريح. النسخة دون صور تحتاج اختياراً صريحاً `--no-media`، ولا تصلح وحدها لاستعادة كتالوج يعتمد على الصور المحلية. الصور وروابط الوثائق في خدمة خارجية لا تُحمّل بهذه الأداة؛ استخدم النسخ وإعدادات الاحتفاظ التي توفرها تلك الخدمة.

تنجح العملية برمز خروج `0` وتعرض الأعداد والمسار فقط. عند الفشل يكون رمز الخروج `1`، وتبقى الملفات الجزئية في المجلد الجديد مع `outcome.json` بحالة `failed` حيث أمكن إنشاؤه. احتفظ بها للفحص أو احذف ذلك المجلد المحدد يدوياً؛ لا تستكمل النسخة الفاشلة ولا تدمج نسخة أخرى فيها. الأداة ترفض أي وجهة موجودة مسبقاً، ولا تعدّل المصدر.

## بنية النسخة

بعد المرحلة A، تتضمن المجموعات تلقائياً `mediaassets` التي تربط الملفات بالمالك والمنظمة والرافع وبصمة البايتات. يجب استعادة هذه المجموعة وملفات الميديا معاً؛ وجود ملف قديم دون سجل ملكية لا يمنحه صلاحية قراءة. لا تنشئ الأداة ملكية تلقائية ولا تنقل أصول الصور عند تغيير مالك منتج. ثبتت استعادة هذا الربط باختبار اصطناعي مستقل ضمن `backend/tests/mediaPrivacy.test.js`؛ راجع تقرير المرحلة A للأدلة، ولا تعتبر الاختبار المحلي اعتماداً لنسخ استضافة فعلية.

- `manifest.json` و`manifest.sha256`: الإصدار والحالة واسم قاعدة المصدر وتوقيت النسخ، وعدد المستندات وأحجام الملفات وSHA-256.
- `collections/*.bson`: مستندات BSON الأصلية متتابعة، تقرأ وتكتب تدريجياً دون تحميل المجموعة كلها في الذاكرة. تحفظ أنواع ObjectId وDate وDecimal128 وLong وInt32 وDouble وBinary وغيرها بدلاً من تحويلها إلى JSON.
- `collections/*.metadata.bson`: اسم المجموعة وخياراتها، مثل validator، وتعريفات الفهارس.
- `media/`: ملفات الصور المحلية مع المسارات النسبية وchecksums.
- `outcome.json`: نتيجة النسخ المختصرة دون URI أو أسرار الاتصال.

الـchecksums تكشف التلف العرضي؛ ليست توقيعاً يثبت أصالة نسخة عدّل مهاجم محتواها وchecksums معاً. لا تشفّر الأداة البيانات. احمِ المجلد بصلاحيات نظام التشغيل، وشفر القرص/الأرشيف عند النقل، وحدد احتفاظاً ونسخة مستقلة خارج جهاز التشغيل. لا ترفع النسخ أو الميديا أو URI إلى Git.

الأداة ترفض symlinks وjunctions، ومسارات الهروب والتصادم، والملفات غير الاعتيادية. مجلدا الصور والنسخة يجب أن يكونا منفصلين. لا تدعم مجموعات النظام أو views أو time-series أو encrypted collections؛ تستخدم هذه الحالات أدوات MongoDB الأصلية وخطة استعادة مناسبة. كما لا تنسخ مستخدمي MongoDB أو الصلاحيات أو الأسرار أو إعداد replica set أو oplog.

## اختبار الاستعادة

اضبط `RESTORE_MONGODB_URI` من مدير الأسرار/البيئة، دون كتابته في سطر الأمر، ثم اختر قاعدة اختبار فارغة **مختلفة** عن المصدر وعن قاعدة `MONGODB_URI` الخاصة بالتطبيق. يجب أن يحتوي URI الاستعادة أيضاً اسم قاعدة صريحاً، لكن `--target-db` هو الذي يحدد وجهة الاستعادة فعلياً.

```powershell
node scripts/restore.js --archive "D:\JomlaBackups\pilot-2026-10-19-01" --target-db jomla_restore_20261019 --confirm-target jomla_restore_20261019 --media-target "D:\JomlaRestore\media-20261019"
```

المجلد الأب لوجهة الميديا يجب أن يكون موجوداً، والوجهة نفسها يجب أن تكون جديدة. المقارنة مع اسم المصدر واسم قاعدة التطبيق تتم حتى لو اختلف الخادم. أسماء `admin` و`config` و`local` ممنوعة. لا يوجد `--drop` أو خيار لتجاوز هذه القيود، ولا تعديل لأي مجموعة موجودة. يجب أن تكون قاعدة الهدف فارغة بالكامل، وأن تبقى معزولة عن التطبيق وعن أي كاتب آخر طوال الاستعادة. لن تحوّل الأداة التطبيق تلقائياً إلى القاعدة أو الصور المستعادة.

تفحص الأداة manifest وكل checksums وبنية كل مستند BSON وأعداده ومسارات الملفات، قبل الاتصال بالهدف أو كتابة مستند فيه. ثم تنشئ المجموعات والفهارس وتعيد المستندات على دفعات والميديا بملفات جديدة، وتراجع أعداد المستندات وchecksums الميديا المنسوخة. البيانات المقروءة أثناء الاستعادة يجب أن تكون من نسخة موثوقة وغير قابلة للتعديل المتزامن؛ ليست الأداة حداً أمنياً ضد تغييرات نظام الملفات المتزامنة.

تكتب النتيجة في ملف `restore-<database>-<uuid>.json` بجوار مجلد النسخة. يمكن تحديد ملف جديد بـ`--outcome`. هذا الملف خارج النسخة والميديا، ويعرض النجاح أو الخطأ المنقح والأعداد ونتائج التنظيف. أخطاء الشروط الأولية، مثل تأكيد غير مطابق أو ملف تالف، ترفض العملية مباشرة وتُعرض على stderr قبل إنشاء موارد الاستعادة؛ عندئذ قد لا يوجد outcome على القرص.

الاستعادة **ليست ذرية على مستوى قاعدة البيانات** ولا تستخدم معاملات. عند فشل الكتابة تحاول الأداة حذف المجموعات التي أنشأتها تلك المحاولة فقط، والمجلد الجديد الذي أنشأته للميديا. لا تستخدم `dropDatabase()`، ولا تحذف مجموعة موجودة قبل المحاولة. قد يفشل التنظيف بسبب انقطاع الشبكة أو الصلاحيات؛ يذكر outcome ما حذف وما تعذر حذفه. راجع النتيجة واعزل الهدف إلى أن يكتمل الفحص؛ لا تعتمد على rollback شامل مضمون.

بعد نجاح الاستعادة، افتح نسخة تطبيق معزولة موصولة بقاعدة الاختبار ومجلد الميديا المستعاد، وقارن الأعداد، وجرّب تسجيل الدخول والكتالوج وRFQ وافتح عينات من الصور. احتفظ بسجل التاريخ والنسخة ومدة الاستعادة والنتيجة ومسؤول الاختبار. لا تختبر ذلك على قاعدة الإنتاج، ولا تغيّر بيانات التشغيل لإثبات الاختبار.

## التحقق الآلي المتاح

```powershell
cd backend
node --experimental-vm-modules node_modules/jest/bin/jest.js tests/backup.test.js --runInBand
```

يحتاج Jest إلى `--experimental-vm-modules` لأن MongoDB driver الحالي يستخدم dynamic import لوحدة نظام التشغيل؛ التشغيل العادي للأداة بواسطة Node لا يحتاج هذا الخيار. الاختبار يستعمل MongoMemoryServer وقاعدة وميديا مصطنعتين فقط. يتحقق من تطابق BSON بايتياً بعد الاستعادة، بما فيه ObjectId والتاريخ والأعداد الدقيقة وBinary وDecimal128، ومن الفهارس وvalidator والمجموعات الفارغة والصور والأعداد، ورفض المصدر والإنتاج والأسماء غير الآمنة والتأكيد الخاطئ والوجهات الموجودة والتلف ومسارات الهروب وjunctions، وتنظيف الموارد المنشأة عند فشل كتابة متعمد. نجاحه لا يمثل نسخة احتياطية من بيانات المستخدم ولا اختبار استعادة تلك البيانات.
