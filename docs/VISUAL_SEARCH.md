# البحث البصري المحلي

البحث يقرأ بكسلات JPEG وPNG وWebP وGIF بواسطة `sharp` ويقارن **متجهات خصائص محلية** للون والتوزيع المكاني والحواف. يعمل دون مفتاح ذكاء اصطناعي، ودون تحويل الصورة إلى كلمات أو استخدام اسم الملف. هذه المرحلة ليست CLIP أو نموذج فهم دلالي أو إثباتاً لهوية المنتج.

## عقد الخدمة

- `indexProduct(productId, { actorId, beforeWrite })` يخزن فهرس الصورة الرئيسية ويعيد `indexed` أو `unindexed` مع السبب، أو `stale` إذا تغير مرجع الصورة أثناء التنفيذ. صلاحية استدعائه مسؤولية المسار/عامل المهام؛ الدالة داخلية وليست API عامة. يستطيع العامل تمرير `beforeWrite` غير متزامن لإعادة فحص الصلاحية والإلغاء قبل كل حفظ/حذف؛ رفضه يوقف الكتابة ويصل إلى العامل كما هو.
- `searchImage(buffer, { filters, pagination })` يعيد منتجات الحقول العامة المعتادة، إجمالي النتائج وترقيم الصفحات، و`visualSearch` الذي يشرح إصدار المحول وحد التشابه ومعنى الدرجة وعدد الصور غير المفهرسة/القديمة. يدعم فلاتر المدينة والفئة والمورد والعملة والكمية وشرائح السعر والترتيب، و`q` كقيد نصي اختياري على المرشحين؛ لا يحول تعذر الصورة إلى بحث نصي.
- `matchType: exact` مع `matchBasis: exact_image` يعني تطابق **بايتات ملف الصورة SHA-256 فقط**، ولا يثبت أن السلعتين متماثلتان أو أصليتان. اختلاف الحجم/الضغط يُصنف `similar_image` حتى لو كانت درجة التشابه 1.
- `similarityScore` هو تشابه جيب التمام في المجال 0–1، وليس احتمال صحة أو نسبة دقة. الافتراضي الأدنى `0.82`؛ يحتاج معايرة على صور المنتجات الفعلية.
- المعلومات الداخلية، ومنها المتجه وهاش الصورة وهوية من قام بالفهرسة وحقول الاعتماد، لا تُعاد في استجابة البحث.

## أمن الصور ومنع نتائج قديمة

مصدر الفهرسة المقبول هو اسم صورة `/uploads/name.ext` ضمن `UPLOADS_DIR` (افتراضياً `backend/uploads`). يتم التحقق من المسار الحقيقي لمنع الخروج عبر الروابط الرمزية. لا تجلب الخدمة أي عنوان خارجي، ولو ظهر في منتج منشور. الصور الخارجية تصبح `unindexed / remote_or_unsupported_source` حتى تُستورد بعملية مرخصة ويرفعها المورد ويعتمدها.

السقف 10 ميغابايت، 25 مليون بكسل و12000 بكسل لأي بعد. يتم فك الإطار الأول فقط من الصور المتحركة وتُرفض الأنواع الأخرى والملفات الفاسدة. هذه حدود للموارد وليست ماسح برمجيات خبيثة. راجع [توثيق مُنشئ sharp وحدود الإدخال](https://sharp.pixelplumbing.com/api-constructor/)، و[معالجة الصور والألوان](https://sharp.pixelplumbing.com/api-operation/)، و[إخراج البكسلات الخام](https://sharp.pixelplumbing.com/api-output/).

كل فهرس يحمل إصدار الخوارزمية ومرجع المصدر وSHA-256 للبايتات. البحث يعيد تطبيق `publicCatalogFilter`؛ المسودات والمورد المعطل والمتجر غير المعتمد/المعلق والمنتج المحجوب لا تظهر حتى لو بقي فهرسها في القاعدة. يرفض اختلاف المرجع، ويعيد قراءة المرشح المطابق للتحقق من هاش الملف الحالي قبل إظهاره، فيمنع عرض نتيجة فهرس قديم بعد استبدال الصورة حتى لو بقي العنوان نفسه. لا توجد إعادة فهرسة تلقائية ضمن طلب البحث؛ شغّل المهمة عند تغيير الصورة وبالعملية الدورية للمصالحة.

## التشغيل والفهرسة

من `backend` وبعد إعداد `MONGODB_URI` و`UPLOADS_DIR` الخاصين بالبيئة:

```powershell
node scripts/index-visuals.js --help
node scripts/index-visuals.js --public-only --limit 500
node scripts/index-visuals.js --apply --public-only --limit 500
node scripts/index-visuals.js --apply --product 0123456789abcdef01234567
```

الأمر دون `--apply` قراءة فقط. عند `hasMore: true` أعد التنفيذ مع `--after` وقيمة `nextAfter`. الفهرسة متسلسلة محدودة الحجم، وقابلة لإعادة التشغيل. `--actor` اختياري لتسجيل هوية المشغل الداخلية. لا تعتمد الصور الخارجية أو حقوق الصور تلقائياً ولا تغير حالة نشر المنتجات.

إعدادات اختيارية:

```dotenv
VISUAL_SEARCH_MIN_SCORE=0.82
VISUAL_SEARCH_MAX_CANDIDATES=5000
```

البحث الحالي مقارنة خطية محلية للكتالوج العام المصفى، بسقف 5000 افتراضي (20000 كحد أعلى قابل للضبط). عند تجاوز السقف يعيد خطأ `503 / VISUAL_INDEX_CAPACITY` صريحاً؛ لا يخفي جزءاً من الكتالوج وراء نتائج تبدو مكتملة. الانتقال إلى ANN/مخزن متجهات ونموذج مدرب يحتاج قياساً فعلياً وقراراً معمارياً قبل التوسع.

## قياس قابل للتكرار وحدود الدقة

```powershell
node scripts/index-visuals.js --benchmark
npm test -- --runTestsByPath tests/visualIndex.test.js
```

الـ benchmark يولد 6 صور تركيبية مختلفة اللون والشكل، ويبحث بنسخ مكبرة ومعاد ضغطها JPEG، ويطبع ترتيب المرشح الأول ودرجة النسخة المتوقعة. لا يتصل بقاعدة بيانات ولا يعدل صور المستخدم. الاختبارات تغطي التطابق البايتاتي، التشابه بعد تغيير الحجم، اختلاف الصور، صيغ الصور، التصفية والعزل والترقيم واستبدال المصدر. نتائج هذه المجموعة **ليست قياساً لدقة السوق**.

لاختيار حد مناسب للتجربة، اجمع بموافقة الموردين مجموعة مستقلة من صور الهواتف: نفس الصورة، نفس المنتج من زوايا/إضاءات مختلفة، منتجات شبيهة ومنتجات مختلفة. وسّمها يدوياً واعزل مجموعة الضبط عن مجموعة القبول. قِس Top-1/Top-5 واسترجاع المطابق وتكلفة النتائج الخاطئة لكل فئة، ثم وثق حد التشابه المختار. اللون والخلفية والتكوين قد تطغى على هوية المنتج، وقد يفشل هذا المحول في الزوايا والقص والإضاءة والعناصر المتشابهة. لا يمكن استنتاج خصائص تجارية أو سعر أو توافر من المتجه.

## توافق StrictDraftPrivacy — المرحلتان A وC1

تبقى `/uploads/<filename>` مرجعاً داخلياً للملف ويقرأ العامل القرص مباشرة، بينما تعرض الواجهة الصورة بجلب من `/api/media/<filename>` إلى Blob. منذ C1 يقرأ الزائر صورة مسجلة مرتبطة بمنتج عام مؤهل دون JWT؛ الصور الخاصة تحتاج التفويض المصادق نفسه في A. قبل قراءة البايتات للفهرسة أو إعادة نتائج البحث، يطابق المحول سجل `MediaAsset` ومالك المنتج وحجم الملف وSHA-256. لا يعتمد ملفات قديمة غير مسجلة، أو أصلاً تابعاً لمورد آخر، أو بايتات استبدلت في مسار أصل ثابت؛ يلزم رفع جديد مصادق عليه. لا يجلب الصور البعيدة ولا ينقل ملكية الصور القديمة تلقائياً. تبقى تصفية النشر والمتجر والمورد الحية مطبقة على البحث، حتى عند وجود فهرس قديم. أثبتت اختبارات A وC1 عمل العامل والبحث والاستعادة مع هذا العقد.

### حدود البحث المجهول — C1

فتح قراءة صور الكتالوج لا يفتح الرفع الدائم. مسار `POST /api/image-search` الموجود مسبقاً يقبل استعلام صورة في الذاكرة دون تسجيل أصل أو كتابة ملف، ويطبق حدود فك الصورة والحجم ومعدل20 طلباً في الدقيقة. اختُبر بطلب اصطناعي مجهول واستُعيدت نتيجة عامة مع بقاء عدد MediaAsset والملفات ثابتاً؛ بعد تعليق المتجر اختفت النتيجة حتى بوجود فهرس سابق. يبقى `POST /api/product-ai/upload` مصادقاً، ولا يوجد حفظ مجهول أو ربط صورة مجهولة بمنتج جديد.

لا يعني ذلك اعتماد بحث بصري مجهول شامل: الدقة السوقية والحمل ومكافحة إساءة الاستخدام في الاستضافة غير مقاسة، والمحول محلي محدود، والاكتشاف الخارجي يحتاج إعداد مزود مستقل ولم يُفعّل هنا. لم توسع C1 الرفع المجهول أو مسار AI ولم تغير صلاحياته.
