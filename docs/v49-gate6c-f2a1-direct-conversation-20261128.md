# Gate 6C.3A.1 (F2) - direct pre-RFQ conversation backend - 2026-11-28

**PASS: scoped backend increment; F2 remains OPEN.** Baseline 6dea9089c90f47f40442a766e22ac4ee84e4bfbc.

- New independent DirectConversation model and authenticated API. Buyer starts with a text message for a visible public product. Supplier identity is resolved server-side from that product; deterministic thread identity binds buyer, supplier and product. Owner supplier and buyer participants only. Other buyers/suppliers, staff and admins cannot access the new private conversation route. No automatic RFQ, offer, trade confirmation, review eligibility or response-speed credit. Explicit DTOs omit stored participant IDs, phone and email (user-entered text may contain personal data). Private no-store and scoped list/detail. Based on OWASP API1 object-level authorization guidance (https://api-security.owasp.org/editions/2023/en/0xa1-broken-object-level-authorization/).
- Durable single-document first write and conditional atomic append. UUID v4 per sender role per thread; exact content replay returns original receipt, changed content conflicts. Confirmed write readback; generic uncertain failure rather than false success. Journaled writes. No silent message deletion: maximum 200 messages/thread, 2000 characters/message, 20 threads/page, page <=1000; provisional per-actor 30 write attempts/15min in-process limiter alongside existing commercial IP budget. No attachments or arbitrary sender/recipient fields.
- Read-only history if product/store/owner no longer public/active or buyer inactive. Review narrowed product lookup to exact current supplier, and permits exact first-message recovery after product is hidden while rejecting new writes; if deleted/transferred, recover existing thread from list instead. No cross-document transaction; visibility can change between check and write. Snapshot display names, not live contacts. Limits are engineering choices, not final product policy.
- First targeted BE 103/103 (5 suites), 47.190s, exit 0. Review added two regressions for lost creation acknowledgement after product hidden and independent actor write budgets. Final fresh BE 105/105 (5 suites, including 8 direct-conversation tests), 44.566s, exit 0. Tested concurrent create and append, duplicate/conflicting keys, lost append acknowledgement, unauthorized roles and objects, hidden products, suspended stores, inactive buyer, capacity race and request limits; existing RFQ, review, security tests still passed. Isolated disposable wiredTiger MongoDB, synthetic accounts. [Sanitized evidence](evidence/v49-gate6c-f2a1-20261128/summary.json).
- No UI or browser acceptance, no notifications, unread counts, push/live delivery, user block/report, moderation workflow, attachment support, retention policy, multi-process abuse budget or production-scale verification in this increment. These remain explicit obligations before release. No claim of end-to-end encryption. Staff access deliberately excluded until separate permissions policy. No original data changes, dependencies or deployment. Original V4.9 reference and original checkout unchanged.
- Video not implemented: ffmpeg/ffprobe were not found on current PATH. Existing image validation/storage cannot safely be reused by extending file extensions alone. Separate verified video validation, ownership, controlled playback and range handling, limits and publishing rights needed.
