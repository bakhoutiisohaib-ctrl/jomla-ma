## Implementation
- Verification-specific service reserves a private embedded operation using conditional, journaled supplier updates before any verification state mutation. Binds actual authorized actor, previous status, revision and operation input. Blocks conflicting/new transitions while reserved/applied/cancelled. Existing owner same-dossier replay and completed admin decision rejection retained.
- Upserts audit intent using the reserved operation ObjectId and verifies identity before applying the supplier mutation. Pending intent survives failures; no successful verification response until store projection, completed audit and final receipt are confirmed. Disabled supplier before mutation cancels the reserved operation with failed audit. A previously authorized reservation can be recovered without a new decision; no new discretionary decision is introduced by the worker.
- Store projection has monotonic revision/status stamp; a delayed earlier worker cannot undo a newer submission's projection. Public store trust already derives from canonical supplier status. Private and admin store lists and edit/review responses derive badge from the current supplier. Store creation seeds projection and can return an explicit projection-pending flag if its post-create synchronization fails, rather than falsely reporting creation failure. No new public verification authority.
- Bounded worker wired to API startup/shutdown: default batch 25, maximum 100, capped exponential delay, automatic retry stops after ten recorded failures. Matching original owner/admin request can recover its active receipt. Internal operation metadata not returned in supplier responses. No change to generic auditedChange behavior.
