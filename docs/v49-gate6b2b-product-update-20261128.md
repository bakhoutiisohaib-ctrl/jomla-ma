## Implementation
- Existing ProductEditor uses original product editRevision and authenticated actor, with a secure attempt key and X-Product-Revision on PUT. No unkeyed fallback when revision or actor is missing. Existing creation POST flow, upload, taxonomy, price/quantity, explicit rights and publication review remain intact.
- Scope sessionStorage metadata by actor and product. Store only key, baseRevision and intended draft flag, before sending; freeze exact JSON body in mounted editor memory. No product content, image payload or credential in attempt storage. Refuse new PUT when storage cannot be verified. Session/unmount cancellation and single-flight guard retained.
- Validate PUT acknowledgement version, product identity, revision, draft state and indexing status; independent private keyed lookup must confirm saved revision before success. Uncertain attempts lock editing. Same mounted attempt retries original body/key; after reload user explicitly queries status, and saved status is corroborated by authorized current product read. No automatic write on reload.
- Distinguish absent, saved and superseded. A stale editor cannot overwrite newer revision. Explicit current-version review fetches actual server state, replaces unsaved inputs with warning and remounts editor; absent does not prove a delayed request cannot arrive. Saved-but-index-unavailable retains original attempt for same-key enqueue repair while mounted, or explicit return with an indexing warning after rechecking saved state. Reload does not restore original payload; never invent it. Existing save success callback remains compatible.
- Recovery-only panel moved above ordinary steps and focuses/scrolls into view after mobile visual review; ordinary V4.9 wizard, layout, card design and CSS unchanged. Arabic/French/English recovery labels.

## Limits and next
R2 accepted for implemented local keyed editor flow, not all historical/client or cross-document races. Session metadata survives same-tab reload, not guaranteed across closing/clearing tab or other devices. Payload is memory-only; after remount no original unsaved data or same-body replay. Read-only recovery reports indexing uncertainty rather than claiming a job exists; explicit current-version review can abandon an absent attempt, whose delayed write could still win CAS before a later save. Latest receipt can be superseded; no complete audit history or automatic repair of superseded indexing gaps. Existing legacy clients, external direct DB writers, production migration, load, physical devices and full final parity remain outside this acceptance. No backend changes or fresh full backend run in this slice. Prior 221/221 backend scope remains separate. No deploy, dependency/default-branch/original DB/reference change.
